# Бот в MAX

Добавлены три файла поверх существующего бэкенда, без изменений в
`database.py` / `filters.py` (логика фильтрации переиспользуется как есть):

- `max_client.py` — тонкий HTTP-клиент к MAX Bot API (`platform-api2.max.ru`),
  реализует `GET /updates` (long polling) и `POST /messages`, напрямую по
  REST-спецификации https://dev.max.ru/docs-api. Официального Python SDK у
  MAX нет (есть только JS/TS/Go), а сторонние пакеты я подключать не стал —
  чтобы не тащить в проект незнакомую и потенциально неподдерживаемую
  зависимость.
- `dialog.py` — конечный автомат диалога: те же вопросы, что в CLI-версии
  `main.py` (бюджет → размер группы → интересы → исключённые категории →
  indoor → еда → шум), только ответы приходят по одному сообщению за раз.
- `bot.py` — точка входа: long polling, по одной `DialogSession` на
  `user_id`, в конце — `get_places()` + `filter_places()` и результат
  текстом в чат.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить DB_* и MAX_BOT_TOKEN
python bot.py
```

## Важно

- Long polling (`GET /updates`) официально не рекомендован MAX для
  продакшена — там ограничения по скорости и сроку хранения событий.
  Для прода в документации советуют Webhook (`POST /subscriptions`). Для
  локального запуска/хакатона long polling проще — не нужен публичный
  URL/HTTPS. Если понадобится webhook-вариант, скажи — вынесу `bot.py` на
  FastAPI/Flask и подписку через `POST /subscriptions`.
- Состояние диалогов хранится в памяти процесса (`Bot.sessions`), при
  рестарте бота все начатые-но-незавершённые диалоги сбрасываются.
- `/start` (или «заново») в любой момент сбрасывает диалог пользователя.
- Результат фильтрации присылается по одному сообщению на место (лимит
  API — 4000 символов на сообщение, а `format_place` компактный, так что
  так надёжнее, чем упаковывать всё в одно сообщение); показываю первые
  8 вариантов, остальные — по запросу через уточнение фильтров.
