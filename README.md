# Бот подбора места для встречи в MAX

Бот помогает компании выбрать место для встречи с учётом интересов, бюджета,
времени в пути, часов работы и занятых интервалов. Участники могут заполнить
анкеты сами в общей комнате или один человек может указать данные за всех.
Подходящий вариант можно сохранить как бронь **в базе бота**; это не
бронирование в заведении.

## Запуск через Docker

### Что понадобится

- Docker с поддержкой команды `docker compose`;
- доступ в интернет для загрузки образов и работы с MAX API.

Запускайте команды из корня репозитория. Python и PostgreSQL на компьютере
для этого сценария не нужны. Дамп тестовой базы (`data/DataBase.backup`) и
сертификаты для подключения к MAX (`certs/`) уже включены в проект.

1. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

2. Откройте `.env` и проверьте `DB_PASSWORD` и `MAX_BOT_TOKEN`: там должны
   быть пароль вашей базы и токен вашего бота. Задайте также свой
   `PGADMIN_PASSWORD`, если планируете пользоваться pgAdmin. Файл `.env`
   содержит секреты и исключён из Git.
3. `DB_PASSWORD` устанавливается самостоятельно (любой пароль).
4. Соберите и запустите сервисы:

   ```bash
   docker compose up --build -d
   ```

   При первом запуске PostgreSQL восстанавливает базу из дампа и создаёт
   таблицу `bot_bookings`. Бот и pgAdmin запускаются после проверки готовности
   базы. Первый старт может занять больше времени, чем последующие. 
5. Проверьте состояние и журнал бота:

   ```bash
   docker compose ps
   docker compose logs --tail=100 bot
   ```

   Успешный вход в MAX API отмечается строкой `Бот запущен: ...`. Найдите
   своего бота в MAX и отправьте ему `/start`. Бот работает через long polling,
   поэтому адреса веб-приложения и открытого порта у него нет.

### Настройки

Все параметры берутся из `.env` в корне проекта. Образец с комментариями —
в [`.env.example`](.env.example).

Так выглядит `.env` для этого проекта. Значения пароля и токена ниже —
заполнители: подставьте свои и не публикуйте их в репозитории.

Базовый логин и пароль для PgAdmin: admin@admin.com и admin и изменяются в .env
```dotenv
# PostgreSQL
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=<пароль_базы>

# Для запуска Python на компьютере, без Docker
DB_HOST=localhost
DB_PORT=5432

# Бот MAX
MAX_BOT_TOKEN=<токен_бота>
# MAX_NO_PROXY=1

# Необязательные настройки Docker
# DB_HOST_PORT=5433
# PGADMIN_PORT=5050
# PGADMIN_EMAIL=admin@admin.com
# PGADMIN_PASSWORD=<пароль_pgadmin>
```

Строки с `#` — комментарии: раскомментируйте нужную настройку, удалив `#`.
Если пароль содержит пробелы или `#`, заключите значение в одинарные кавычки;
символ `$` в пароле для Compose запишите как `$$`. Указывайте значения без
пробела после `=`.

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `DB_PASSWORD` | Пароль PostgreSQL; обязателен | нет |
| `MAX_BOT_TOKEN` | Токен бота MAX; обязателен | нет |
| `DB_NAME`, `DB_USER` | Имя базы и пользователь PostgreSQL | `postgres` |
| `DB_HOST`, `DB_PORT` | Адрес и порт БД при локальном запуске Python; в Docker переопределяются | `localhost`, `5432` в `.env.example` |
| `DB_HOST_PORT` | Порт PostgreSQL на компьютере | `5433` |
| `PGADMIN_PORT` | Порт интерфейса pgAdmin на компьютере | `5050` |
| `PGADMIN_EMAIL`, `PGADMIN_PASSWORD` | Учётная запись pgAdmin | `admin@admin.com`, `admin` |
| `MAX_NO_PROXY` | `1` — подключаться к MAX без системного прокси | пусто |

В контейнере бот всегда подключается к базе по адресу `db:5432`;
значения `DB_HOST` и `DB_PORT` из `.env` используются только при запуске
Python напрямую на компьютере. PostgreSQL и pgAdmin доступны с компьютера
только через `127.0.0.1`.

Если `DB_NAME` или `DB_USER` отличаются от `postgres`, настройте подключение
в pgAdmin вручную: готовая запись сервера в `docker/pgadmin/servers.json`
рассчитана на значения по умолчанию.

### pgAdmin и работа с контейнерами

После запуска откройте [http://localhost:5050](http://localhost:5050)
(или порт из `PGADMIN_PORT`). Войдите с `PGADMIN_EMAIL` и
`PGADMIN_PASSWORD`. Для подключения к серверу «Meeting bot DB» используйте
пароль `DB_PASSWORD`. С компьютера PostgreSQL доступен по адресу
`127.0.0.1:5433` (или по порту из `DB_HOST_PORT`).

```bash
docker compose logs -f bot   # текущий журнал бота
docker compose logs db       # восстановление базы и ошибки PostgreSQL
docker compose restart bot   # перезапустить бота
docker compose down          # остановить сервисы, сохранив данные
```

Данные PostgreSQL и pgAdmin хранятся в именованных томах Docker. Повторный
`docker compose up` **не** загружает дамп заново. Команда ниже удаляет оба
тома, включая все новые записи и брони, и при следующем запуске база будет
создана из исходного дампа:

```bash
docker compose down -v
```

После первого запуска изменение `DB_NAME`, `DB_USER` или `DB_PASSWORD` в
`.env` не перенастраивает уже созданную базу. Если бот не запускается,
посмотрите `docker compose logs bot` и `docker compose logs db`: частые
причины — неверный токен, пароль или ошибка подключения к MAX.

## Как пользоваться ботом

Отправьте `/start` и выберите режим:

- **Комната** — организатор создаёт комнату, приглашает друзей по ссылке или
  командой `/join КОД`; каждый заполняет свою анкету, затем организатор
  запускает подбор.
- **Самостоятельно** — один человек вводит условия и анкеты всех участников.

Бот предлагает места и поясняет ограничения. Нажатие кнопки бронирования
создаёт запись в `bot_bookings`, но не связывается с заведением. Подробности
сценариев и ограничения описаны в [документации бота](docs/BOT.md).

## Разработка

Основные части проекта:

| Путь | Содержимое |
| --- | --- |
| `run_bot.py`, `app/bot/` | Запуск и сценарии диалога |
| `app/core/` | Подбор мест, маршруты, расписание |
| `app/max_api/`, `app/db.py` | Работа с MAX API и PostgreSQL |
| `docker-compose.yml`, `Dockerfile`, `docker/` | Контейнеры и начальная загрузка БД |
| `sql/`, `data/DataBase.backup` | Схема и тестовые данные |
| `Generators/` | Генераторы синтетических данных |
| `tests/` | Автоматические проверки |

Для запуска без Docker используйте Python 3.13 (версию из `Dockerfile`) и
доступную базу PostgreSQL с применённой схемой. Установите зависимости,
заполните `.env` и запустите бота:

```bash
python -m pip install -r requirements.txt
python run_bot.py
```

Базу для локальной разработки можно запустить командой `docker compose up -d db`.
Если PostgreSQL поднят через Compose, для локального Python укажите в
`.env` `DB_HOST=localhost` и `DB_PORT=5433` (либо значение `DB_HOST_PORT`).
Эти же настройки нужны генераторам из `Generators/`. Проверки без базы:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Описание модели данных и алгоритмов — в [docs/DATA_MODEL.md](docs/DATA_MODEL.md).
Комнаты и незавершённые диалоги хранятся в памяти бота и пропадают при его
перезапуске; записи `bot_bookings` сохраняются в PostgreSQL.
