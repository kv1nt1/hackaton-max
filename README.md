# Бот подбора места для встречи (MAX)

Бот в мессенджере MAX помогает компании друзей выбрать место, подходящее
всем. Два режима:

- **🏠 Комната** — друзья заходят по ссылке, каждый сам указывает интересы,
  бюджет и откуда поедет; бот подбирает место по самым частым интересам;
- **🎯 Самостоятельно** — один человек вводит данные за всю компанию.

Учитываются бюджет, интересы, формат места и **время в пути каждого
участника** по графу синтетического города. Если идеального места нет,
показывает ближайшие варианты и объясняет, что именно не совпало.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env          # заполнить MAX_BOT_TOKEN и DB_*
# положить сертификаты Минцифры в certs/ (см. certs/README.md)
python run_bot.py
```

Тесты (БД не нужна):

```bash
pip install -r requirements-dev.txt
pytest
```

## Структура проекта

```text
├── run_bot.py            точка входа бота
├── app/
│   ├── bot/              всё, что про диалог в мессенджере
│   │   ├── bot.py          обработка событий MAX, сценарий встречи
│   │   ├── dialog.py       вопросы об общих условиях (кнопки), их правка
│   │   ├── participant.py  анкета участника: интересы, бюджет, район, транспорт
│   │   └── meetings.py     встречи и участники (пока в памяти)
│   ├── core/             логика подбора, не зависит ни от MAX, ни от БД
│   │   ├── filters.py      строгий и «мягкий» фильтры
│   │   ├── routing.py      время в пути по графу дорог (Dijkstra)
│   │   └── recommend.py    отбор и ранжирование мест
│   ├── max_api/client.py   HTTP-клиент MAX Bot API
│   ├── db.py               доступ к PostgreSQL
│   └── dictionaries.py     справочники: перевод кодов БД на русский
├── generators/           генераторы синтетических данных (город, места, люди)
├── sql/                  схема БД, файлы пронумерованы в порядке применения
├── data/DataBase.backup  дамп БД
├── scripts/cli_search.py консольный поиск без бота
├── tests/                автотесты
├── certs/                сертификаты Минцифры
└── docs/
    ├── DATA_MODEL.md     модель данных и алгоритмы (подробно)
    └── BOT.md            как работает бот, ограничения
```

Правило зависимостей: `core` ничего не знает про `bot`, `bot` — про SQL.
Поэтому логику подбора можно тестировать без БД и мессенджера.

## Генерация бронирований

После применения `sql/07_bookings.sql` и заполнения мест, встреч и участников:

```bash
python Generators/generate_bookings.py --dry-run  # посмотреть данные без записи
python Generators/generate_bookings.py            # добавить бронирования в БД
```

Подключение берётся из `.env` в корне проекта. Генератор использует `SEED = 42`,
создаёт до трёх последовательных посещений на встречу, учитывает количество
участников, пересечение их доступности и часы работы места. Встречи без
подходящих мест пропускаются; итоговая статистика показывает охват.
Это тестовые бронирования, а не результат алгоритма рекомендаций:
интересы, бюджет и маршрут здесь не проверяются.

По умолчанию существующие записи сохраняются; повторный запуск добавит ещё
один набор. Для полной перегенерации можно указать `--replace` — он удалит
**все** существующие бронирования. Параметры `--seed` и `--max-per-meeting`
позволяют изменить набор и максимум посещений.

## Заметки

- Групповые бронирования хранятся в `bookings`: встреча, место, начало и
  конец посещения, количество человек, статус и примечание. Одна встреча
  может иметь несколько бронирований. Схема: `sql/07_bookings.sql`
  (применяется после файлов `01`–`06`). Для существующей БД применить только
  новый файл, не запускать предыдущие схемы повторно:

  ```bash
  psql -h "$DB_HOST" -p "${DB_PORT:-5432}" -U "$DB_USER" -d "$DB_NAME" -v ON_ERROR_STOP=1 -f sql/07_bookings.sql
  ```

  Команда предполагает, что переменные `DB_*` уже экспортированы в shell;
  `psql` сам не читает `.env`. Подробности — в `docs/DATA_MODEL.md`, раздел 5.9.

- Комнаты хранятся в памяти процесса и пропадают при перезапуске. Когда
  появятся новые таблицы, заменить нужно только `MeetingStore` в
  `app/bot/meetings.py`.
- Пароли и токены — только в `.env` (в Git не попадает).
