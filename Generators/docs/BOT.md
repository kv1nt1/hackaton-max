# Как работает бот

## Старт

`/start` показывает выбор режима:

- **🏠 Создать комнату** — для компании, где каждый сам вводит свои данные;
- **🎯 Выбрать самостоятельно** — один человек вводит всё за всех.

Сразу после выбора режима бот спрашивает **дату встречи** (сегодня/завтра
или вручную в формате ДД.ММ) — она нужна, чтобы сверяться с часами работы
мест и с уже существующими бронями.

## Режим «Комната»

1. Организатор создаёт комнату, указывает дату и заполняет свою анкету:
   интересы, бюджет, район, транспорт, лимит времени в пути, **с какого и
   до какого часа свободен**.
2. Бот присылает ссылку-приглашение и код (`/join КОД`).
3. Каждый участник заполняет такую же анкету сам.
4. Организатор нажимает «Найти место». Результат получают все.

Организатор может менять **общие условия** комнаты («⚙️ Общие условия»),
не пересоздавая её. Каждый участник может обновить свои данные
(«✏️ Мои данные»).

## Режим «Самостоятельно»

Как раньше, но перед общими вопросами бот спрашивает дату встречи, а в
анкете каждого участника есть ещё и его личное свободное время.

## Подбор мест

1. **Жёсткие условия**: место вмещает компанию, категория не исключена,
   цена не выше бюджета больше чем на 50% (бюджет компании — минимальный
   из бюджетов участников).
2. **Интересы — только самые частые.** Раньше бот искал сразу по всем
   интересам всех участников: в комнате из 8+ человек это обычно 15-20
   разных тегов, и почти любое место хоть чем-то да зацепится. Теперь
   считается, у скольких участников встречается каждый тег, и в поиск
   идут только **до 3 самых частых** (`TOP_K_INTERESTS` в
   `app/core/recommend.py`), да и то с порогом «встречается минимум у
   двух участников» — если совпадений нет ни у кого (маленькая компания,
   у всех разные вкусы), порог снимается и берутся любые до трёх.
3. **Дорога** каждого участника — по графу города, как раньше.
4. **Часы работы и брони — новое.** Считается общее свободное окно
   компании (пересечение личных `available_from/until`; если пересечения
   нет — берётся объединение и об этом сообщается отдельной пометкой).
   Для каждого места проверяется:
   - работает ли оно вообще в это окно в выбранный день (с учётом смен
     через полночь);
   - есть ли в открытое время свободный интервал длиной с визит
     (`avg_duration_minutes`), не пересекающийся с уже существующими
     бронями из таблицы `bot_bookings`.
   Если свободное время нашлось, оно показывается в результате
   («🗓 Можно успеть: 18:00–19:30») и место можно сразу забронировать.
   Если нет — это тоже мягкий штраф (место не пропадает, просто получает
   пометку и опускается ниже).
5. Прочие мягкие условия (помещение/улица, еда, шум) — как раньше.

Сортировка: штраф → сколько человек интерес места покрывает → максимальное
время в пути (справедливость) → среднее время → рейтинг.

## Бронирование

Под каждым местом, для которого нашлось свободное время, — кнопка
«📅 Забронировать №N». Нажать может только организатор (в режиме
«самостоятельно» — тот, кто всё вводил). Бот записывает бронь в
`bot_bookings` (место, время, число человек, кто забронировал) и
уведомляет остальных участников комнаты.

`bot_bookings` — отдельная таблица, не часть вашей схемы `bookings` /
`meetings` / `friend_groups`: та требует создавать «настоящую» встречу с
привязкой к группе друзей, а у бота более лёгкая модель (комната по коду
или разовый подбор без комнаты вообще). Бронь бота соединяется с общими
данными только через `place_id -> places(id)`, поэтому существующая схема
не затронута. Если понадобится перенести бронь бота в «настоящую» таблицу
`bookings` — для этого сначала придётся завести соответствующую запись в
`meetings`/`friend_groups`.

При повторном поиске уже забронированное время учитывается: то же место
предложат на следующий свободный интервал после брони, а не на тот же час.

## Ограничения

- Комнаты и диалоги хранятся в памяти; максимум 10 участников; комната без
  активности удаляется через 48 часов.
- Местоположение участника — район города (представительная точка), а не
  точный адрес.
- Часы работы и брони проверяются только на выбранный день, без повторов
  «каждую неделю».
- Используется long polling. Для продакшена MAX рекомендует webhook.
